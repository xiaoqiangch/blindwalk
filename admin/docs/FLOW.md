# 一次完整的运营流程（可照着做）

> 前提：`bash scripts/start-admin.sh` 已启动，浏览器打开 http://127.0.0.1:8802/admin

## 1. 抓一批候选（收集整理）

右上角 **「抓取附近」** → 填坐标和半径（例如 31.2304 / 121.4737 / 1200）
→ 后台从中文维基百科地理搜索真实地标（带图片），落成 `草稿`。

结果会提示：`新增 6 条，跳过 0 条`。

## 2. 让模型过一遍（整理）

勾选几条 → **「AI 整理」**
- 有 Key：模型按这个地点的简介，写出「为什么是这里 / 小任务 / 三条线索」
- 没有 Key：用离线类别模板生成（右上角会写「离线规则模式」）

## 3. 人工编辑（编辑处理）

点任意一条，右侧面板改：
- 名称、类别、稀有度、区域
- 简介（120 字）、为什么是这里、小任务
- **三条线索**：输入时实时检查是否含地名，含了会标红并禁止保存
- 图片 URL + 署名

`Cmd/Ctrl + S` 保存。

## 4. 判断能不能上（分析判断）

勾选 → **「AI 分析」**
- 有 Key：模型给出 `safety.score`（1–5）、是否适合步行、人流密度、结论 `good/risky/reject`
- 没有 Key：规则打分（有图 +1、公园河岸 +1、hints 含地名 -3、缺 why/task -1）

觉得可行的 → **「通过」**；不合适的 → **「拒绝」**（不会导出）。

## 5. 导出上架

点 **「导出到 App」** → 只导出 `已通过` 的点，写到 `prototype/web/pois.json`。

App 端下次打开盲盒时，**优先**从这里挑（距离合适范围内），抽到时会标「编辑精选」。

## 6. 怎么知道 App 用上了

App 抽盒后：
- 提示 `这是编辑精选的地点`（而不是「附近找到 N 个真实地标」）
- 揭晓卡右上角标 **编辑精选**
